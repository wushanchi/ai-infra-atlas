LEARNING PATHS & PROJECTS

学习路径与实战项目

根据当前岗位目标选择一条主线压缩学习，不必机械完成全部资源。每条路径串联若干阶段；每个实战项目对应一次能力跃迁，并可作为 GitHub 仓库或团队教程沉淀。

三条推荐学习路径

主线 · 24–32 周

系统级 AI Infra

适合建立完整技术树，覆盖从硬件到生产的全链路。

  1. AIInfraGuide + MLSysBook 建全景
  2. CS149 / CUDA MODE + Triton
  3. UW / CMU LLM Systems
  4. mini-infer → vLLM / SGLang
  5. NCCL → Dynamo / llm-d
  6. GuideLLM + Nsight 做优化闭环
专项 · 12–18 周

模型推理系统

适合当前直接投入推理优化工作。

  1. 模型执行与 KV Cache 核算
  2. tiny-llm / mini-infer 跟练
  3. vLLM Anatomy + Mini-SGLang
  4. FlashAttention / FlashInfer
  5. P/D 解耦与集合通信
  6. 多引擎 Benchmark 与 Trace
平台分支 · 16–24 周

国产 NPU / 昇腾 CANN

把通用系统知识映射到当前工作平台。

  1. 通用 GPU/NPU 性能模型
  2. Ascend C 编程与 Tiling
  3. CANN 推理框架课程
  4. cann-recipes-infer 源码映射
  5. HCCL 与并行策略分析
  6. MindStudio Profiling 闭环

七阶段能力目标

每个阶段都设定一个可检验的能力目标，学完该阶段应能达成。

四个阶段性实战项目

每个项目对应学习顺序中的一个能力跃迁，并能沉淀为 GitHub 仓库或团队教程。

项目 01 · 对应阶段 4

教学型推理引擎解剖

选 mini-infer、Mini-SGLang 或 tiny-llm，画出 Request → Scheduler → KV Cache → ModelRunner → Kernel → Response 的完整数据流。

交付物：架构图、关键类调用链、一次完整请求 Trace 和模块对照表。
项目 02 · 对应阶段 3

Attention / GEMM Kernel 对照

使用 Triton、FlashAttention/FlashInfer 实现或分析同类算子，比较数据布局、Tiling 和带宽瓶颈。

交付物：Roofline 估算、Kernel benchmark、Profile 报告和跨平台差异总结。
项目 03 · 对应阶段 5

分布式推理通信模型

为 TP、EP、P/D 解耦建立 α–β 模型，并将 NCCL/NVSHMEM/DeepEP 的实测结果映射到模型。

交付物：拓扑图、通信量公式、微基准曲线和并行策略推荐。
项目 04 · 对应阶段 6

生产负载 Benchmark 闭环

用 GuideLLM/GenAI-Perf 生成并发、固定速率和 sweep 流量，对 vLLM/SGLang 测 TTFT、ITL、吞吐、尾延迟和饱和点。

交付物：版本锁定配置、CSV/HTML 报告、Trace 证据、优化前后回归结论。

学习方法论

先依赖、后专题先理解模型执行、硬件和性能模型，再进入框架新特性，避免只记 API 名称。
教程与源码配对每学一项机制，至少在教学型仓库或生产仓库中找到对应实现和调用链。
结论必须可测任何“更快、更省显存”都应绑定模型、硬件、流量、版本和指标定义。
跨平台抽象把 CUDA/NCCL 知识抽象成并行层次、存储层次、通信原语和运行时，再映射到 CANN/HCCL。
